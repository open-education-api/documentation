# Abbreviations and definitions

## Abbreviations

| Abbreviation                     | Meaning |
| -------------------------------- | ------- |
| API                              | Application Programming Interface. A way for software systems to communicate and exchange data with each other. |
| CEFR                             | Common European Framework of Reference for Languages. A European framework for describing language proficiency. |
| COIL                             | Collaborative Online International Learning. An educational approach in which students and staff from different institutions collaborate online across national and institutional boundaries. |
| ECTS                             | European Credit Transfer and Accumulation System. A European system for expressing study workload and supporting the recognition and transfer of study achievements. |
| EU                               | European Union. A political and economic union of European countries. |
| HBO                              | Hoger beroepsonderwijs. The Dutch higher professional education sector, primarily provided by universities of applied sciences. |
| HORA                             | Hoger Onderwijs Referentie Architectuur. The reference architecture for Dutch higher education, providing a shared framework for describing organisations, information and information systems. |
| ISCED-F                          | International Standard Classification of Education: Fields of Education and Training. An international classification for categorising fields of education and training. |
| MBO                              | Middelbaar beroepsonderwijs. The Dutch secondary vocational education sector. |
| NT2                              | Nederlands als tweede taal. Dutch as a second language, referring to Dutch language education for non-native speakers. |
| OEAPI                            | Open Education API. In Dutch, the standard was originally known as the Open Onderwijs API, hence the former abbreviation OOAPI. OEAPI is a standardised API specification, developed within the OEAPI Community in close collaboration between educational institutions, suppliers and SURF. Using this API, educational institutions can make useful information available, such as grades, study credits, schedules and available workstations. Application developers can use this data to develop and integrate new applications and services. |
| OOAPI                            | Open Onderwijs API. The former Dutch name of the Open Education API and the origin of the former abbreviation OOAPI. |
| ROSA                             | Referentie Onderwijs Sector Architectuur. The reference architecture for the Dutch education domain, providing a shared framework for processes, information and systems. |
| SIS                              | Student Information System. A system used by an educational institution to manage student and education-related administrative data. |
| SURF                             | The collaborative organisation for IT in Dutch education and research. SURF facilitates the OEAPI Community and contributes to the development and management of the standard. |

## Definitions

| Term                             | Definition |
| -------------------------------- | ---------- |
| Bureau Edustandaard              | [Bureau Edustandaard](https://www.edustandaard.nl/over-edustandaard/bureau-edustandaard/) is a partnership between SURF and Kennisnet responsible for managing and advising on education-specific and research-specific standards and manages ROSA, the reference architecture for the Dutch education domain. The bureau facilitates the Standardisation Council, the Architecture Council and the Edustandaard working groups. It also maintains relationships with other national and international standards organisations. The Standardisation Council consists of directors of educational institutions and public and private organisations. |
| Code repository                  | The [Open Education API organisation on GitHub](https://github.com/open-education-api) contains the code repositories used for the development and maintenance of the OEAPI specification, documentation and related resources. |
| Community                        | The OEAPI Community consists of parties interested in OEAPI developments, including educational institutions, suppliers and other interested parties. Community members share knowledge and experience and contribute to the further development, implementation and adoption of the standard. |
| Consumer                         | A consumer is a system or application that uses data provided by an OEAPI implementation. |
| Consumer profile                 | A consumer profile allows an OEAPI implementation to provide additional data or apply presentation rules for a specific consumer. A consumer profile is a request mechanism and not an authorisation mechanism. |
| Edustandaard.nl and the ROSA-wiki | [Edustandaard.nl](https://www.edustandaard.nl/) and the [ROSA Wiki](https://rosa.wikixl.nl/) provide information about the OEAPI standard. They provide information about the specification, its relationship with other standards and architectures in the context of HORA and ROSA, its use and implementations, and related documentation. |
| Implementation                   | An OEAPI implementation is a technical implementation of the OEAPI specification by an educational institution, supplier or other organisation. It exposes education-related data through an API that conforms to a particular version of the specification. |
| Implementer                      | An implementer is an educational institution, supplier or other organisation that implements the OEAPI specification. |
| Mailing list                     | Members of the Technical Working Group are subscribed to the mailing list, which is intended for communication between members of the working group. Users can [subscribe through the SURF mailing list service](https://list.surf.nl/postorius/lists/openonderwijsapi.list.surf.nl/). |
| Project site                     | The [OEAPI project site](https://oeapi.eu/) provides information about OEAPI to interested parties. The site also provides access to the specification, documentation and other resources related to the development, implementation and use of the standard. |
| Release                          | A release is a published version of the OEAPI specification and its accompanying documentation. Releases allow implementers and consumers to refer to a specific, stable version of the standard. |
| Repository                       | A repository is a version-controlled collection of files used to develop and maintain OEAPI. The OEAPI repositories are hosted in the [Open Education API organisation on GitHub](https://github.com/open-education-api). |
| Specification                    | The OEAPI specification formally describes the data model, endpoints and behaviour for exchanging education-related data using OEAPI. |
| Specification repository         | The OEAPI specification and its various versions are maintained in the [GitHub specification repository](https://github.com/open-education-api/specification). Changes to the specification are developed, reviewed and maintained in this repository. |
| Standard                         | OEAPI is an open standard for exchanging education-related data. The standard comprises the specification and the agreements required to enable interoperable implementations by educational institutions, suppliers and other parties. |
| Technical Working Group          | The OEAPI Technical Working Group is responsible for annual planning, development, management, promotion, community, communication, adoption and evaluation of the Open Education API specification. The working group consists of members from various educational institutions, suppliers and SURF. |
| Use case                         | A use case describes a situation in which OEAPI is used to exchange education-related data to meet a particular need. Use cases help identify, explain and validate requirements for the specification. |
| Version                          | A version identifies a particular edition of the OEAPI specification. Versioning allows implementers and consumers to determine which specification and associated agreements apply to an implementation. |
